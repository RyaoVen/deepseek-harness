# @deepseek-ai/dsh-extensions-center

[English](README.md) | 中文

扩展中心：一个由设置驱动的 MCP 服务器与技能挂载界面，管理入口位于「插件」设置页内的一个标签页。

**Node 半端是实时再同步器，不是静态读取器。** 它注册 `extensions-center` 设置命名空间（schema 默认值、`live` 生效时机，以及一个拒绝它无法执行的配置段的校验器——重复 id、超出 mcp-client 命名空间预算的 id、所选传输方式用不到的字段、非法或重复的技能名、空技能正文），并在每次提交变更后重新同步。每个启用的服务器条目通过 `ctx.plugin` 挂载为独立的 mcp-client fiber，条目中的传输字段映射为 mcp-client 配置；被停用、移除或连接相关字段变更的条目会释放其 fiber，变更的启用条目会被重新挂载。每个启用的技能条目被渲染为技能根目录下的 `<name>/SKILL.md`（默认为 `$DSH_HOME/skills`，即每个默认 skill-filesystem 提供方都会扫描并监听的用户根目录），因此这里的写入无需重新配置即可让每个会话的目录失效；被停用或移除的条目会删除其目录。扩展中心从不改动它不拥有的文件。启动失败的挂载会被记录并丢弃，下一次设置变更会重试；`failOnStartupError` 默认关闭，因此一个坏服务器条目不会拖垮应用。

**浏览器半端是「插件」设置页中的一个标签页。** 它向 `settings.plugins.tab` 贡献一个 `extensions` 标签页（order 20，位于随附的配置标签页之后），页面通过设置作用域读取同一个命名空间，并提供两组内容：MCP 服务器与技能。每组列出条目，带启用开关、可展开的编辑表单与移除操作，外加一个收起的添加表单；条目以整份草稿编辑，每次操作都会重算整个数组并以一次路径写入写回，宿主回读是唯一权威——未落地的写入会让视图保持诚实并标记保存失败。

## Model Experience

间接，经由它挂载的 MCP 服务器（每个启用条目都会成为 mcp-client fiber，其工具注册到 `ctx.tools`）以及它写入技能根目录的技能文件（skill-filesystem 提供方拥有目录及其模型可见条目）——因此所有模型可见效果都属于这些提供方，而本包自身不注册任何提示词、工具 schema 或会话事件。

#### KV Cache effect

无：本包不产生任何自身的提示词输入，挂载或卸载扩展既不扩展也不改写历史尾部。

## Known Limitations and Deferred Work

- **技能以文件落地，外部写入的目录可能排在前面** —— 扩展中心写入共享的 `$DSH_HOME/skills` 根目录，同名的手工创建目录会以文件系统提供方赋予的同一等级胜出；扩展中心自身的同步只移除它先前创建的目录。
- **重启重读的是设置文件，不是技能目录** —— 在扩展中心之外删除的技能文件会在下一次设置提交时重新出现，因为扩展中心对照的是自己的文档，而不是目录状态。
- **服务器编辑在保存时生效，而非逐字段生效** —— 条目以整组数组写回，因此两个同时编辑同一分节的浏览器标签页会按写入竞争；设置修订围栏确保落败方不会静默覆盖胜出方，落败方的视图会重新读取并显示拒绝。对启用服务器字段的保存修改会释放并重新挂载该服务器，因此编辑活动条目时可见的代价是一次短暂的连接中断。
- **stdio 服务器条目会挂载真实的子进程** —— 扩展中心将条目原样传给 mcp-client，因此对设置文件可能命名的命令需要保持惯常的谨慎；该条目是用户自己设置文档中的用户编写数据。
