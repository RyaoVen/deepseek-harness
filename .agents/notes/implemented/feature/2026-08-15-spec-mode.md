# Agent Note: Spec mode with user-led design and one-pass cluster execution

Status: implemented

English | [中文](2026-08-15-spec-mode.zh.md)

## Problem

The vibe cluster owns the execution process but not the design: the product manager guesses and the architect decides, which fits a "just build it" request. The requested spec mode inverts the first half — the USER leads the design discussion down to module level — and then must still execute the whole delivery in one pass, without re-running the clarification phases the user already settled.

## Decision

`spec` joins the `AgentMode` union, and the `vibe` tool's canned script gains three spec-mode prefills: `requirements` (a confirmed requirements archive), `design` (a confirmed module-level technical design), and `styleGuide` (a confirmed style guide). Each prefill skips the matching cluster phase — product manager, architect, or UI designer — while the engineers, the test engineer, and the escalation loop always run. The script fails loud when a prefilled design lacks the module shape (`modules` with `id`/`title`/`layer`/`tasks`/`acceptance`).

The spec-mode guidance section drives the interactive first half: the agent asks the user about goals, constraints, technical preferences, and the module breakdown until the user confirms a module-level design, then runs the `vibe` tool once with the confirmed requirements and design prefilled — "确认后全量并行执行 vibe 流程一气呵成".

## Alternatives considered

- **A separate spec tool** — a dedicated tool beside `vibe`. Rejected: the cluster script is the same; prefills are just earlier phases already settled, so one tool with optional prefills keeps the execution path singular.
- **Design in the mode prompt only** — the spec guidance says "discuss, then call vibe"; the cluster would re-run PM/architect with the discussion in the request text. Rejected: re-clarification wastes agents and can drift from what the user confirmed; the prefills make the user's decisions authoritative inputs.
- **Validation of prefills** — re-validate prefilled designs against the architect schema. Rejected for the shipped shape: the design came from a user-confirmed discussion, so only the shape the script depends on (`modules` array) is checked, loudly.

## Consequences

- Spec mode has one deterministic arc: user-led discussion to module level, then a single `vibe` call executes the cluster in one pass with the confirmed artifacts.
- The vibe script and schema grow three optional parameters; the popup and the mode vocabulary grow the fifth mode.
- Prefill misuse fails loud at the module-shape check instead of silently mis-executing.
