# Agent Note：带硬性工具拦截的设计模式

Status: implemented

[English](2026-08-15-design-mode.md) | 中文

## Problem

模式系统此前只提供建议性模式：模式只改变提示词段落，从不改变工具集，因此设计会话仍可读文件、跑命令——这正是"设计模式 — 仅思考与出方案，禁读写与命令"必须禁止的。强制属于模式包，而非循环。

## Decision

`design` 加入 `AgentMode` 联合（`standard`/`creative`/`design`），`@deepseek-ai/dsh-agent-modes` 的宿主平面新增一个工具守卫，挂载在与模式服务相同的 `apply()` 内，因此现有 Web 宿主行即可激活它，无需新增接线。

守卫监听 `tools/pre-execute` 瀑布——与审批门相同的接缝，因此拒绝在任何能力运行前物化为普通工具错误。它从 `exec.agent.session.events` 折叠调用 agent 的模式，在设计模式下拒绝文件读写工具族（`read`、`write`、`edit`、`read_image`、`glob`、`grep`）与命令执行器（`bash`、`pwsh`），并给出模型可见的理由；其余调用一律放行。无 agent 的调用永不被拦截，非设计模式也从不拦截。

设计模式指引文本（提示词段落）告诉 agent 默认把资料搜集与论证委托给 subagent 并汇总其发现——即"主 agent 汇总"回路——而守卫保持研究工具（web 搜索、subagent、技能）可用，因为设计模式按构造委托研究。

## Alternatives considered

- **仅提示词指引** —— 只有段落文本说"不要读文件、不要跑命令"。拒绝：建议性文本在提示词漂移、重试与多轮压力下会失效；issue 明确要求禁令（禁），而 pre-execute 瀑布在不改循环的前提下即可强制。
- **守卫放 agent 平面** —— 每个 agent 域各自注册监听器。拒绝：工具注册表是宿主平面的，瀑布已通过 carrier 作用域按 agent 路由；一个宿主平面监听器用同一折叠覆盖所有会话。
- **工具类别注册字段** —— 给工具定义加 `category` 再按类别拦截。拒绝：工具 schema 没有类别字段，加一个要改所有注册；拦截清单是模式自身的策略常量，放在模式词汇旁边即可。

## Consequences

- 设计模式会话无法通过标准工具面读、写或执行命令，即使模型试图调用也会被拒；拒绝是模型可路由的普通 `isError` 工具结果。
- 研究工具保持可用，因此设计工作流（把研究委托给 subagent、汇总为方案）可在模式内运行。
- 模式联合、命令弹出层、模式指引、工具目录类型声明与包 README 都增加第三种模式；折叠与切换测试覆盖它，守卫另有独立单元测试（设计模式拒绝、其余放行、无 agent 调用永不拦截）。
