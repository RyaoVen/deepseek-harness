# Agent Note：带固定 agent 集群工作流的 Vibe 模式

Status: implemented

[English](2026-08-15-vibe-mode.md) | 中文

## Problem

模式系统已提供建议性模式与一个强制模式（design），但要求的 vibe 模式是一种流程而非行为：固定 agent 集群——产品经理、架构师、UI 设计师、前端/后端工程师（每模块可多实例）、测试工程师——带问题逐级反上报，以及产品/架构/UI 层的用户决策点。

## Decision

`vibe` 加入 `AgentMode` 联合，新工具包 `@deepseek-ai/dsh-tool-vibe-workflow` 把集群作为 canned 工作流放到既有 `ctx.workflowEngine` 接缝上——与 `workflow` 工具相同的引擎，因此解析、执行、上限、取消与子 agent 派生都留在既有边界之后。

`vibe` 工具接收 `request`（以及上次运行的可选 `answers`）并运行一个 canned 脚本：产品经理澄清并整理需求档案（能问就直接问用户，否则返回开放问题）；UI 设计师与架构师并行；架构师的模块按模块各派生一名前端和/或后端工程师（多实例扇出），每人分 part 实现并逐 part 写单元测试；测试工程师全盘 review 交付物；报告的问题升级到架构师，由其分派修复，工程师应用，测试工程师验证。

用户决策按设计路由到调用 agent：子 agent 未必拥有 `ask_user` 工具，因此脚本以 `needs-input` 返回开放问题，主 agent 询问后带答案重跑——"产品/架构/UI 可直接询问用户决策"通过任一可用路径成立。vibe 模式指引段落告诉 agent 使用 `vibe` 工具并在 needs-input 时循环。

## Alternatives considered

- **仅指引的 vibe** —— 只有模式文本说"你自己用 workflow 工具编排集群"。拒绝：固定集群需要固定脚本；手写编排每次调用都会漂移，并失去结构化角色/阶段契约。
- **新引擎** —— 在 `workflowEngine` 之外建专用集群执行器。拒绝：引擎接缝已提供脚本、阶段、上限、取消与子 agent 派生；工具只需增加 canned 脚本与其 schema。
- **集群状态放模式包** —— agent-modes 拥有工作流。拒绝：工具面应与其他 workflow 工具（`tool-workflow`、`tool-ralph`）相邻；agent-modes 保持模式词汇与强制，模式指引引用该工具。

## Consequences

- Vibe 模式只有一个确定性流程：一次工具调用跑完整个集群，needs-input 运行带答案续跑而非重来。
- 集群有界：单轮升级、引擎并发与总 agent 上限、父回合阻塞到运行静默。
- Web 面新增一个工具行，`/mode` 弹出层新增一项；base bundle 挂载该工具，因此任何有 `workflowEngine` 的面都能使用。
- canned 脚本是包常量，由测试钉住（语法、阶段、角色、无模板字面量隐患）；工具的引擎交接、停止原因映射与无 agent 守卫用 stub 引擎做单元测试。
