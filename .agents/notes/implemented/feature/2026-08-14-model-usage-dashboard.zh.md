# Agent Note：模型消耗仪表盘——基于持久会话日志的四类图表

Status: implemented

[English](2026-08-14-model-usage-dashboard.md) | 中文

## 问题

Web GUI 中模型消耗不可见：没有任何界面能回答「我的模型用了多少调用与 token、在什么时间」。会话日志本就携带适配器上报的用量，但没有人把它们折叠成仪表盘，所要求的「模型消耗仪表盘（热力图/星图/折线图/扇形图）」没有归属。

## 决策

两个新包实现只读用量仪表盘。

`@deepseek-ai/dsh-host-usage-dashboard` 是仅 Remote 的服务（`UsageDashboardGateway`，命名空间 `usageDashboard`，方法 `summarize`），折叠每条持久会话日志：通过 `sessionPersistence.listSnapshots` 枚举已物化会话，折叠每个携带适配器上报用量的 `assistant/message` 事件（跳过非模型来源与无用量事件），按模型、按 UTC 日、按 UTC 时段分桶，并合并为一份 `UsageSummary`。会话按持久化修订缓存，因此第二次调用只重读存储日志发生变化的会话；被移除的会话会被逐出；加载失败的会话会被跳过并记录。折叠是对日志的纯求和（`fold.ts`），重放与压缩都无法改变它。

`@deepseek-ai/dsh-client-ui-usage-dashboard` 注册一个设置分区（`settings.section` id `usage`，order 10，位于「插件」分区之前），页面将汇总渲染为四张手写 SVG 图表：以周一为锚的 12 周日历热力图（0–4 级调用强度）、头部四个模型在五个归一化维度（调用、输入、输出、缓存读、缓存写）上的雷达星图、30 天总 token 趋势折线图，以及带图例的按模型占比环形图。所有图形形状都是纯投影（`projections.ts`）；样式只使用主题 token，图表随强调色与深色模式变化。控制器拥有加载生命周期：挂载即首次读取，读取进行中拒绝刷新，失败读取标记到下次刷新。

接线沿用既有的 Remote 模式：宿主包携带生成的 `./remote`/`./typert` 工件，api-remotes 客户端组装挂载该命名空间，Web 组合新增一行宿主行与一行客户端行，两个类型检查聚合引用新工程。

## 备选方案

- **由 `session/event` 驱动的进程内实时累加器**——事件到达时计数，而非读取时折叠日志。否决：它把持久日志复制成第二个真相源，错过进程启动前的全部数据，且必须持久化才能跨重启存活；读取时折叠同一份日志是同样的工作量且只有一个真相源。
- **客户端聚合**——把所有会话日志发到浏览器再折叠。否决：为宿主可一次计算并缓存的图表把潜在的大日志量搬过网络。
- **token-meter 的估算**——用 `ctx.tokenMeter` 的压力数字作仪表盘数据。否决：meter 定价的是当前上下文表面，而非持久消耗；仪表盘的契约是从日志得到的按模型/按日记账。

## 影响

- 消耗现在是持久、重放稳定的日志读取：数字回答「适配器上报了什么」，而非估算。
- 折叠成本由按修订的缓存约束；重启后的首次读取会整体折叠一次。
- UTC 分桶保持宿主确定性；本地时坐标轴是客户端后续工作。
- Web 包新增一个宿主 Remote 与一个设置分区；两个包均有单元测试覆盖（折叠、缓存/逐出/失败、投影、控制器、分区、注册）。
